## 五段管线

```
上传 → ingest → read → judge → render → 下载 HTML
        │        │      │       │
        │        │      │       └─ 结构化 JSON → HTML，纯函数，可逐字节 diff
        │        │      └─ 三票判定，产出 verdict / confidence / evidence
        │        └─ DeepSeek Flash，放大后送图，每页两轮
        └─ PDF→PNG、EXIF 旋转、放大 2–3 倍、红笔颜色掩膜
```

### 转写要投票，不能只信一次

同一张图、同一套提示词，两次转写会读出不同的红笔符号和题号——真机上三种结果都见过：

| 运行 | 错题集合 |
|---|---|
| 探针 | 一（2）、二.1（正确） |
| golden | 二.1、二（1）②、（1）、（2）（漏判 + 编造编号） |
| 单页复跑 | 一（4）被判错（老师实际打勾） |

所以转写跑两轮，按相似度对齐逐题投票（题号只是辅助信号）：两轮一致直接采用；不一致补第三轮，两票多数决；
**三轮各不同 → `none`**。选 `none` 是保守：判 unknown 只是让人多看一眼，误判成错会让学生多做一道题。

底稿（正文来源）选「旁证最多、独有最少」的那一轮，平局时取更短的那轮——**不按题数取**：
某轮把同一题抄成两条、或多编几道题时会当上底稿，真实结果反被当成补题追加
（2026-11-21 第 1 页曾膨胀到 17 题）。标记取底稿与所有对得上的轮次的多数决；
另一轮独有的题补进来时，单轮独有且「判错」的必须别轮也能找到同一题才收；
收尾再按「题面核心 + 题号兼容」把同一题的多个抄法归组，**一次看全再定夺**（不先到先得，
否则 ✗ 和 ✓ 谁在前谁赢）：组内只有一种标记就采纳它，两种标记同时出现按「没批」处理；
单成员的组沿用原票，只有真合并过的组才重建票，避免抹掉跨轮分歧、白跑第三轮。

**怎么把两轮的题对上**：按相似度做动态规划对齐，既不是按题号也不是按位置。
题干先归一化（全角转半角、去标点空白）再算二元组 Dice 相似度，与题号是否一致加权成
`0.85 × 题干相似度 + 0.15 × 题号一致`，超过 0.5 才算同一题。

三种情况都要能处理：编号写法在轮次间会变（`一（1）` 与 `1`）、某轮漏一道题、某轮把一行拆成两行。
按题号对齐会让整页翻倍（真机实测 4 题变 8 题）；按位置对齐一遇漏题就整体错位。

### 判定之前的三个加工步骤

转写拿到的原始数据不能直接进判定，先过三道工序（`runPage` 里顺序固定）：

| 步骤 | 模块 | 做什么 | 为什么 |
|---|---|---|---|
| 题干补全 | `judge/stem.ts` | 题干只由标号组成（`（2）`）时，改用同大题最长的题干 | 卷面公共题干写在大题标题里，模型只抄小问标号，导出的卷子上就剩一个「（2）」，学生看不懂要做什么 |
| 墨迹体检 | `judge/ink.ts` | 逐题量标记框里的红/暗像素占比，产出体检报告写进 evidence（`markEmptyBox` / `markNoBox` / `markNoRedInk`），**不改动判定** | 模型会把没批的题报成打了叉；但框和颜色也会骗人（黑笔批改整页 0% 红、框常落在空白处），所以只当「值得人工看一眼」的提示 |
| 三票判定 | `judge/verdict.ts` | 老师标记 / 独立求解 / 规则检查 | 见上一节 |

体检结果只进 evidence，不参与判定；早年「按框把打了叉降级成没批」的规则已在 M9 废除，
理由见下文「红笔复核只记录，不翻案」。

### 没读到 ≠ 没有标记

模型没返回 `teacherMark` 字段时记 `unread`，投票时是弃权票，不占多数决的分母。
两轮都没读到时结果仍是 `none`（保守），而不是被两个 `unread` 凑成"多数"。
如果只看「有没有标记」，漏读会被当成老师没批，正好漏判掉要抓的错题。

### 模型调用的口径

提供方预设集中在 `vlm/providers.ts`，换提供方只改这张表。当前默认 **opencode go** 的 `deepseek-v4.1-flash`
（它的 modalities 含 jpeg/png/webp，图片链路可用），备用 DeepSeek 官方 `deepseek-flash`。

两次调用共用同一个客户端：第一次给图（`detail: "original"`，`low` 会把图压到 512×512 把小字磨掉），
第二次只给题干与图形参数。对外失败一律抛出、不静默降级——判定宁可停，不可拿错结果继续。

### 图形的口径

**模型只报尺寸，坐标一律自己算。** 让模型给坐标，梯形十次里有三次是歪的；尺寸是它能读准的东西。
换算固定为 1 单位（cm）= 26px，四周留白 52px——留白必须算进 `viewBox`，否则内容会被裁掉（M4 第一次实现就栽在这）。

| 类型 | 参数 | 标注 |
|---|---|---|
| `composite` | layout 叠放/并排 + 矩形/三角形/梯形的尺寸 | 每个部件各自的底/宽、高、上底都标出来 |
| `division` | 被除数/除数/商/余 | 除数在左，商在横线上方，余数在下方 |
| `cards` | 数字卡 + 选中项 | 一排圆角卡片，选中项高亮 |
| `unitTable` | 两列数值对 | 表格，行数即数据行数 |

叠放时部件之间留 48px 空隙专门放尺寸线；**梯形上底一定要标**，少一个数学生就算不出面积。

### 渲染的口径

复刻卷是给学生重做的，因此**不出现任何判定痕迹**：没有红笔、没有置信度、没有学生原答案，
原卷题号也不印（重新编号 1..n，避免学生按旧印象找答案）。

- 纯函数：不读盘、不取时间，同一输入两次渲染字节相同（`test/render.test.ts` 有断言）
- 题干来自模型转写，必须 `escapeHtml` 后再拼进文档
- 图形由 `render/figures.ts` 按参数画 SVG（见下节）
- 打印样式：`break-inside: avoid` 保证一道题不被切成两页

### ingest 的具体口径

- **只放大不缩小**：默认 2.5×，长边上限 3000px。V1 反着来（压到 2000px 以内），小字就是那样糊掉的。
- **先摆正再算尺寸**：手机照片带 EXIF 旋转，`sharp().rotate()` 之后拿到的宽高才是真实朝向。
- **红笔阈值**：`r-g ≥ 22 && r-b ≥ 12 && r ≥ 90`。纸张偏黄会抬高 B，所以同时约束两个色差；`r ≥ 90` 挡掉阴影里的暗红。
- **掩膜只做颜色分类**，不做连通域。把标记映射到具体题目在 judge 段做（聚类与对账都在那里）。
- 已知噪声：画面外的红色物体（桌沿、笔）也会被判为红，**还没有**按卷面边界过滤（待办）。

每段的边界：

| 段 | 输入 | 输出 | 是否纯函数 |
|---|---|---|---|
| ingest | 上传的原始文件 | 归一化图片 + 红笔掩膜 | 否（读盘） |
| read | 图片 | `Question[]`（未判定） | 否（调模型） |
| judge | `Question[]` | `Question[]`（有 verdict） | 是 |
| render | `Batch` | HTML 字符串 | 是 |

## 三票判定

| 票 | 来源 | 说明 |
|---|---|---|
| 红笔 | 模型读符号 + 红笔掩膜体检 | 掩膜只做体检（框里有无墨迹），不翻案；符号形状由模型判 |
| 解题 | 第二次模型调用，**看不到学生答案** | 只给题干与图形参数 |
| 规则 | 确定性校验 | 单位换算、面积分割和 = 整体、竖式恒等式 |

收敛规则（固定，不转人工，代码在 `judge/verdict.ts`）：

```
老师 ✗                      → wrong（置信 1.0）
老师 √                      → right（规则票只记 suspicious，不推翻）
老师无标记 + 无求解答案      → unknown
老师无标记 + 规则校验失败    → wrong（置信 0.9）
老师无标记 + 求解与作答一致  → right（置信 0.85）
老师无标记 + 求解与作答不同  → wrong（置信 0.85）——仅当红笔机制可信时
主观题                      → unknown（只转写，不判定）
```

答案比对在 `judge/answer.ts`：全角转半角、上标降级（cm²→cm2）、单位别名
（平方厘米/㎠/cm²→cm2）、0.1% 相对容差。

### 漏批兜底要过「红笔可信」这道闸（M9）

「求解与作答不同 → 判错」这条兜底是为了接住「老师明明打了叉、模型没读出来」的情况。
但它对学生答案的转录噪声极敏感：2026-11-21 的黑笔批改卷上，它一页报了 14 道错题（实际 4 道）。

现在闸门是「红笔机制可信」，两个信号满足其一才启用：

1. `redVerifiedMarks > 0`——至少有一个标记框真的压着红笔簇；
2. 整页红簇数 ≥ 声称的标记数。真机实测：红笔批改的几何卷 7 簇 / 2 个标记（比例 3.5），
   黑笔批改的计算卷 0 簇 / 6 个标记。

两个信号按「或」合成，任一成立就启用，但前面还有一道前置条件：**声称的标记数 > 0**。
一个标记都没声称时直接关闸——否则「整页红簇数 ≥ 0」恒真，黑笔卷上一有零星红印，
兜底就会把整页判成错。

两个信号都得留在公式里，才不会两边翻车：
只留信号 1 会把红笔卷关掉（模型给的框常常偏），只留信号 2 会被红章、红色印刷元素误开。现象对照：

- 黑笔批改：红像素 0%，闸门关闭，只认老师标记；
- 红笔卷但框全偏：信号 2 兜住，兜底照常启用（几何卷的「顾村公园」就是这么判回来的）。

### 红笔复核只记录，不翻案（M9）

`judge/ink.ts` 的 `inspectMarks` 只产出体检报告（`emptyBoxes` / `noBox` / `noRedInk`）并写进 evidence，
**不再改动判定**。原来的「框里没有红笔就降级」有两个致命前提，真机都不成立：

- 老师可能用黑笔批改（整页 0% 红）→ 真错题被全线降级；
- 模型给的 `markBox` 不可靠（同一张图两轮转写，4 个真 ✗ 里有一半的框落在空白处）→ 按框降级误杀真错题。

办法：判定以多轮投票为准，框和颜色只作为「值得人工看一眼」的提示。

## 为什么图形不用模型坐标

模型给出的坐标不可复现：同一张图跑两次，path 不一样，渲染器就无法做字节级 diff。
所以模型只输出**尺寸与分割方式**（`composite` / `division` / `cards` / `unitTable`），
坐标由本地生成器按参数算出。三份人工成品的图全部能用这条路表达。

## 边界

- `packages/core` 不读盘、不联网：图片路径与模型客户端都由调用方注入
- `packages/web` 只做编排与持久化，不写判定规则
- 复刻卷里不出现任何判定痕迹（置信度、三票明细进批次记录，不进复刻卷）
